너는 한국지역난방공사 양산 열원의 정전조작 앱을 만드는 사람이다.
**네가 만든 것이 틀리면 현장에서 사람이 다친다.** 빨리보다 정확히.

## 네가 만지는 것

| 무엇 | 자리 |
|---|---|
| 자료 고치는 SQL | `db/redtag-NN-<무엇>.sql` (번호를 이어 붙인다) |
| 찾기 화면 | `redtag.html` (화면+동작), `redtag.js` (자료 가져오기) |
| 첫 화면 | `index.html` = `사진대장.html` (**둘을 똑같이 유지**) |
| 서비스워커 | `sw.js` — 고칠 때마다 `CACHE_VERSION` 을 올린다 |

## 반드시 지킬 것

### 자료(SQL)
- **여러 번 실행해도 안전하게** 쓴다. 같은 값을 다시 써도 결과가 같게.
- **`delete`·`update` 에 `where` 가 없으면 안 된다.** 전례가 있다 —
  주석엔 "10건만 지운다" 고 적고 조건 없는 delete 네 줄을 둬서, 실행했다면
  자료 전부가 사라질 뻔했다. 지울 대상은 이름을 하나하나 적어라.
- 파일 끝에 **확인용 select** 를 둔다. 전체 건수를 함께 세어, 줄었으면
  바로 보이게 한다.
- 기대값을 주석에 숫자로 적는다("기대: 1358").
- **실행하지 마라.** SQL 은 사용자나 Aside 가 Supabase SQL Editor 에서 돌린다.
  anon 키로는 어차피 SELECT 만 된다.
- 원본(`red-tag-manager`)에 없는 수정은 **배치를 다시 만들면 되살아난다.**
  그 사실을 파일 머리에 반드시 적어라.

### 화면
- 바닐라 JS, 빌드 없음, ES5 꼴을 지킨다(`var`, `function`). 외부 라이브러리는
  `libs/` 에 들어 있는 것만 쓴다.
- **빠지는 것을 만들지 마라.** 목록의 머릿수와 펼친 줄 수가 다르면 그 자체가
  결함이다. 자료에 있는데 화면에 안 나오는 것이 가장 나쁘다.
- PostgREST 는 한 번에 **1,000행**까지다. 목록을 받을 때는 `range()` 로
  끝까지 나눠 받아라. 이 함정에 두 번 당했다.
- 현장은 **폰, 한 손, 장갑**이다. 누르는 자리는 크게, 표는 가로로 안 잘리게.
- 고친 뒤 **반드시 문법 검사**: `node --check redtag.js`, 인라인 스크립트는
  잘라 내서 검사.
- `index.html` 을 고쳤으면 `사진대장.html` 도 같게 맞춘다
  (앱 이름 `뚝 DOC(보고용)` 줄만 다르다).

### 주석
- **왜 그렇게 했는지**를 적는다. 무엇을 하는지는 코드가 말한다.
- 함정을 만났으면 그 함정을 적어 둔다. 다음 사람이 또 빠진다.

### 브랜치
- `sub` 가 개발이자 운영 브랜치다(Vercel Production, 폰에 설치된 앱).
- **`main` 은 절대 건드리지 마라.**
- 커밋만 하고 **push 는 하지 마라** — 호출자가 확인한 뒤 올린다.
